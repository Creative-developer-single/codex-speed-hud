---
name: setup
description: Set up the local Codex Speed HUD plugin and check its desktop connection.
---

Use this plugin's own root (the directory containing this skill is `skills/setup/`; resolve `../..`). It contains a bundled `dist/hud.js` in installed packages and release archives.

1. Check Node.js 22.15+ and the local desktop App. Do not read auth files.
2. If `dist/hud.js` is missing in a source checkout, run `npm ci --no-audit --no-fund` and `npm run build` in the plugin root.
3. On Linux, run `node scripts/desktop.mjs install` to configure the user application-menu entry automatically. This enables the loopback port and starts HUD on each normal ChatGPT launch; no manual debugging command is needed. Never modify system App files or restart an active App. Then run `node scripts/control.mjs start` in the plugin root, then `node scripts/control.mjs status`.
4. If the status says `waiting_cdp`, explain that the desktop App needs its loopback DevTools port enabled. Do not terminate/restart an active App or interrupt a chat. After the user normally quits the App, the configured application-menu entry enables port 9222 automatically; `node scripts/launch-app.mjs` remains a fallback. The existing runner will reconnect automatically.
5. Once `connected`, ask the user to send a normal message in the target chat. A connection with zero observed notifications does not prove live stream support. Check the numeric `notifications` and `states` returned by the status command.

The first-stream latency field measures turn start to the first observed model stream event, including reasoning headers and deltas; it does not wait for visible body text. Native turn TTFT is only a fallback when a full stream start was not observed and must not overwrite an observed latency. This is not a network handshake measurement. Live and reply-average visible tok/s are o200k_base estimates. The average includes intermediate messages under one turnId and resets with the next user turn; historical turns and previous fast-mode replies are excluded. Session token totals include historical uncached input, cached input, and output, without counting cache or reasoning twice. Never claim these represent hidden reasoning throughput or exact decoder speed. Do not upload local chat data, credentials, runtime state or telemetry elsewhere.

The overlay uses a temporary, nonofficial renderer adapter. It does not patch App bundles or send App Server RPCs. Version 0.4.0 removes all model forwarding and routing changes. Native telemetry tails existing logs_2.sqlite read-only and never enables body logging or changes network settings. Only actual native argument deltas can measure tool-generation throughput; current default App logs do not expose them, so report this limitation honestly. Do not use a forwarding proxy, modify chatgpt_base_url, force another transport, inspect auth files or change request headers. The readonly model card stays frozen to completed output metadata.

Compression and tool metrics use the existing first-flow and speed fields, without an extra compression row. Opaque compaction outputs must never be tokenized; output token count divided by total duration is full-duration average throughput, including waiting, not instantaneous decoder speed. Native compression first flow uses observed compaction item start to the first correlated native compaction stream event. Do not claim an unobserved network request start. Historical completion-only records must not fabricate first-flow latency or generation rate.

The speedometer's model card is read-only and shows metadata from the last completed output, never the live composer selection. Capture settings once at turn start and publish them when output ends; native logs can restore the actual model and reasoning effort. Missing historical speed-mode metadata must remain unknown. The card has no picker action or chevron. Do not change the user's model or service tier during setup or checks.

Version 0.4.2 supports an explicitly authorized optional same-version native observation patch. See `native/build.py` and README. Never replace system binaries, proxy model requests, change networking, enable hidden runtime_metrics, or restart an active App. The patch uses an App-supported CODEX_CLI_PATH override on the next normal launch, guarded by original/patched binary hashes. Check `observer.phase` and actual sample count; waiting_native_client means native capture is not active. Native first flow includes response.created and uses local monotonic request timing. The native per-user-turn average includes all completed model outputs and request waiting, while renderer-only average remains visible output.
