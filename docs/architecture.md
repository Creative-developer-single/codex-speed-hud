# Codex Speed HUD

本机 Codex App 插件，在聊天界面上叠加可拖动、收起和关闭的速度面板。通过 CDP 临时注入 Shadow DOM，旁听 App 已收到的 `mcp-notification` 消息。只读本机原生事件与日志，不修改 App 安装包、后端地址、鉴权、请求或上游连接。0.4.0 已移除响应流代理与路由改写入口。

## 码表界面

半圆码表展示实时速率与保留快照，默认量程 0–200 tok/s，超过量程自动扩展。下方分别显示首流、本次回复平均速率和历史累计用量；兼容浅色/深色与窄窗口，尊重减少动画设置。

模型卡片为纯展示，没有点击行为或跳转箭头。卡片与左上角 FAST / 标准标识只显示上一次已结束输出的记录，不随 App 选择器实时改变。在回合开始时一次性记录当时的选择，输出结束后再提交快照；本机日志的实际模型与推理强度用于补齐记录。下一次输出结束前保留上次快照。历史日志未记录速率模式或选择器无法确认时显示待确认，不根据当前选择猜测历史模式。

开始采集回合设置的适配依赖 `data-codex-intelligence-trigger`、`data-selected-reasoning-effort` 及安装版的 ModelPicker DOM。渲染面板时不会轮询该选择器。App 更新可能需要调整。码表、指针与图标由矢量 UI 绘制，图像模型生成的概念稿仅作为设计参考。

## 新会话与当前聊天识别

0.4.1 优先读取当前可见输入区/聊天面板的正式 ID，而不是侧栏的 `client-new-thread` 临时 ID。输入区上方的空 portal 可能被 CSS 隐藏，所以按其所属 composer 的可见性判断；缓存的隐藏聊天面板不参与当前聊天选择。多面板同时可见时按焦点或明确侧栏选择区分，无法确定时不展示猜测数据。同一聊天 ID 跨主机出现时保持主机隔离。

统计从收到 `turn/started` 就按正式聊天 ID 保存，不依赖历史回复或会话日志。第一轮即可计算首流、正文速率和本次平均。正式 DOM 标识较晚出现时仍可显示已经观察到的首轮数据；不以最近收到的后台事件猜测当前聊天。尚无正式 ID 的新输入区显示等待，不沿用旧聊天数值。模型选择仍只在归属已确认的回合开始时读取一次，归属未知时不借用其他聊天的选择。

## 指标

| 显示 | 来源和口径 |
| --- | --- |
| 首流 | `turn/started` 至 App 收到首个模型流事件：思考/正文 item 开始、思考分段头或思考/正文 delta。包括无正文的事件，不等第一个字。不把用户消息、工具 stdout/stderr、工具执行生命周期或用量更新当作模型流事件。已测值不被后续正文或原生记录覆盖；缺少完整事件时可回退到原生 TTFT，悬停说明来源。新回合尚无测量值时保留上次快照，重新附加时从日志恢复最近记录；中途启动不补造起点。这是回合级事件延迟，不是底层 TCP/WebSocket 握手时间。 |
| 速率 | 累计正文用 `o200k_base` 编码，最近约 2 秒的 token 增长率。界面直接显示数值，不展示分词实现细节；数值仍为本地估算，不保证与服务端 tokenizer 完全一致。输出结束后保留最后一次新文字触发的速率采样，直到下一次输出更新；不会在等待时衰减旧快照。 |
| 本次平均速率 | 同一个 `turnId` 下已采集的所有正文 token ÷ 正文流式输出时间，包括中间多条回复和工具循环，排除无正文的工具等待、超过 1.5 秒的停顿和未捕获的历史文字。累计采样满 250 ms 后显示，结束后保留。下一条用户消息产生新 turn 时重新统计，不混入历史回合或之前的 fast 模式。中途启动只统计本次回复已观测到的部分，历史速率无法还原。 |
| 会话累计 tok | 当前聊天全部历史请求的用量，从本机完整会话日志读取逐响应用量并去重；流事件的 `tokenUsage.total` 作补充。未缓存输入＋缓存输入＋输出，即总输入＋输出，缓存和推理不重复相加。不是当前上下文长度。K=千、M=百万、B=十亿。 |

累计栏显示 `27.25M/12.34$`：当前聊天累计 token 数 / 估算模型费用。按每条去重响应的实际模型、输入、缓存输入、缓存写入和输出逐次计费；推理与工具参数已包含在输出中。支持混合模型、Fast / Priority、Ultrafast；日志有明确服务等级时优先使用。回合开始时捕获的 Fast 设置只用于这一回合，并在本机保存数字元数据以便插件重启后恢复。未记录速率模式的历史请求按 Standard 估算，悬停注明数量；未知模型或不完整用量显示 `—$`，悬停显示已知部分，避免误报为零费用。小于一美分显示 `<0.01$`。这是官方 API 等价模型费用，不是订阅账单，不计外部工具服务费。

后台每日从[官方 API 价格表](https://developers.openai.com/api/docs/pricing)读取 Standard、Fast、Ultrafast 等价格，首次启动带有 2026-10-12 查询得到的价格快照；网络失败保留上次成功价格，详情见状态文件 `pricing`。价格请求只访问公开文档，不发送会话内容。

按本项目用户指定规则，GPT-6.1 Sol 的长上下文阈值设为单次请求**总输入大于 500,000**，并按该档对整条请求计价，不依据会话累计 tok 判断。2026-10-12 查阅的官方模型页和价格页仍写 272K，因此 500K 是用户指定覆盖值，不宣称已经由官方文档证实。可用 `CODEX_SPEED_HUD_SOL_CONTEXT_THRESHOLD=272000` 恢复文档当前阈值（重启采集进程生效）；其他模型使用官方价格表阈值。

`o200k_base` 是公开的文字分词编码：一个 token 可能是一个词、词的一部分、标点或汉字片段，并不等于一个字。它用于实时正文估算；会话累计用量直接采用 Codex 记录的 token 数，不重新分词。

工具执行、超过约 1.5 秒无正文、完成、中断时保留此前的速率快照；尚未采到有效速率时显示 `—`。快照按聊天和主机隔离，悬停提示说明是否为上次输出。每条消息最多暂存 256K 字符；超过上限暂停估算。结束后丢弃正文，只保留数字。不会将 `output - reasoning` 当作纯屏幕正文 token；它还可能包含工具参数。

## 使用

要求 Node.js 22.15+，桌面 App 支持 Electron loopback DevTools。Linux 自动发现当前 ChatGPT App 与部分 Codex 安装路径；macOS 提供启动路径适配，尚未做本机验证。Windows 请使用 `CODEX_SPEED_HUD_APP` 指定可执行文件。

Linux 发布包已带运行依赖，优先使用 `node scripts/install.mjs` 完成安装与自动启动配置，之后正常打开 ChatGPT 即可。下面的手动启动命令仅用于源码开发和排查。

修改源码后构建：

```bash
npm ci --no-audit --no-fund
npm run build
```

先启动采集进程：

```bash
node scripts/control.mjs start
node scripts/control.mjs status
```

若返回 `waiting_cdp`，需要在**正常退出当前桌面 App 后**用以下方式打开。启动器不会终止正在运行的聊天，也不会强制退出 App：

```bash
node scripts/launch-app.mjs
```

也可在正常退出 App 后用 `node scripts/launch-hud.mjs` 一次完成 App 与 HUD 启动。

调试端口限制在本机 `127.0.0.1:9222`。采集进程会等待 App、自动重连、重新注入。打开目标聊天并发送消息后才开始采集流数据；历史回复不伪装成实时样本。`connected` 仅证明附加成功，`states[].notifications > 0` 才说明实际观察到支持的通知。

可以通过 `CODEX_SPEED_HUD_CDP=http://127.0.0.1:9333` 更改采集端点；通过 `CODEX_SPEED_HUD_PORT=9333` 更改启动器端口。更换采集端点时先停止旧进程。

```bash
node scripts/control.mjs stop
```

停止会移除已附加窗口中的 HUD 和刷新注入脚本。正常重新启动 App 且不传调试参数会关闭调试接口。界面上的“×”仅隐藏当前面板；右上角工具栏码表按钮可以随时重新打开，隐藏期间继续采集。

## 原生客户端本机观察补丁（0.4.2）

补丁基于与当前安装客户端一致的官方版本 `0.162.0-alpha.17.2`、提交 `740e5af33c71225640e0c1c1555c514c2c93ab74`。它只在现有 HTTP/SSE 与 WebSocket 请求中增加本地观察对象，在原生 JSON 解码后借用选定字段；没有新增模型代理、修改 URL、鉴权、请求头/正文、TLS、连接池、重试或协议选择。`runtime_metrics` 在当前官方版本为隐藏开发功能，仍不启用，不添加 `x-responsesapi-include-timing-metrics`。原有外部依赖全部保留，仅添加离线分词依赖。源码不变不等于重新构建后的二进制或连接时间逐字节一致，采集本身仍有有限的本机开销。

首流使用原生单调时钟，从原生 API 请求开始至第一条响应事件（含 `response.created`），不是首个可见文字。暖连接的 `generate=false` 请求排除。工具参数按各调用的真实收包时间及累计分词估算速率，并行工具共用请求时间轴，不把重叠时间重复相加。压缩加密内容不复制、不分词，只根据结束用量计算整个调用的平均吞吐。原生工具、压缩与首流仍复用原有面板；没有新增压缩行。

分词和文件发布在独立后台线程，网络流任务只作有界 `try_send`。队列最多 256 条、单段最多 16 KiB、每个请求暂存文本总计最多 256 KiB、最多 64 个工具、128 个请求。溢出或丢样会将该请求指标标为不可用。结束/中断清除参数，闲置 10 分钟清理样本。只发布标识、时间、数字和枚举字段到权限 0700 的 `native-metrics/`；文件权限 0600，原子替换。不发布提示词、认证、请求头、参数文本或加密内容。

构建并验证可选客户端：

```bash
python3 native/build.py
```

需要 Rust、Python 和源码构建依赖。脚本验证官方压缩包哈希、匹配安装版本、原有依赖未变、所有观察点以外源码未变，运行原生测试及只使用假凭据的本机流式对比，成功后才写 `native-client/enabled.json`。已构建时可用 `--stage-existing` 重做源码审计和对比并暂存。正式包仅携带补丁和构建脚本，不携带巨大源码/构建缓存。

用户级启动器在下次正常打开 App 时通过它现有的 `CODEX_CLI_PATH` 支持选择补丁客户端，保留官方启动参数和 originator；不覆盖系统文件，不终止当前 App。当前 App 内的原生进程不能热加载新二进制；HUD 的更新可以热加载。每次启动验证官方二进制与补丁二进制哈希，App 升级或文件改变时自动回退原客户端。已有其他自定义客户端时保持其选择。`observer.phase=observed` 和真实样本才证明已经采集，`connected` 仅指 HUD 连接。

关闭补丁：删除或将 `~/.cache/codex-speed-hud/native-client/enabled.json` 的 `enabled` 改为 false，下次正常打开 App 恢复官方客户端；当前会话不受影响。

## 工具参数与压缩采集

0.4.0 只读 `~/.codex/logs_2.sqlite`（SQLite `readOnly` + `query_only`），从附加后的尾部增量采集原生日志。每轮最多扫描 4096 条记录，单条最大 1 MB，不开启额外日志、不接管模型连接、不读取认证文件。只保存聊天/回合/响应标识、时间与数值；已有日志中的文本仅在内存中短暂解析，工具参数在输出结束或流超时后释放。采集器不可用时保留 UI 指标，状态注明 `telemetry.phase`。

当前安装版会记录 `response.compaction.compacting`，可按明确聊天和回合标识匹配实际观察到的压缩生命周期：压缩 item 开始至首条原生压缩流事件为首流。它不是 TCP/WebSocket 握手时间，也不是未经观测的底层请求起点。压缩结束并获得原生输出用量后，使用输出 tok / 压缩总耗时更新速率，含等待。加密压缩项不分词。缺少起点、事件或用量时不补造指标。

工具参数解析器支持已有原生日志中的 `response.function_call_arguments.delta`、`response.custom_tool_call_input.delta`、`response.mcp_call_arguments.delta`，按原生日志时间计算增量速率，不用轮询时间推算。只有同进程、同聊天、同回合且请求归属明确的事件参与；并发归属不明确时跳过。已记录请求开始时可测首流；中途附加只有增量时可以测速率，但首流未知。插件不会为了获得这些日志改变 WebSocket/SSE 协议或开启包含请求内容的 TRACE 日志。

默认官方 App Server 没有工具参数增量通知，本机默认日志也没有这些增量。0.4.2 增加可选的同版本原生客户端采集补丁，启用并正常重新打开 App 后，可以在解码后、事件过滤前采集真实工具参数增量。仅安装 HUD 或连接 CDP 不代表原生采集已经运行。

压缩与工具参数复用现有的**首流、速率**，没有额外行。下一次正文或工具参数有更新的有效测量时更新；缺失数据保留旧快照。未启用原生补丁时，`本次平均`仍按本次正文流计算。启用后按同一用户 turn 内已完成的所有调用计算：总输出 token ÷ 总请求耗时，含首流等待、推理、工具参数和压缩；不统计工具执行 stdout，不含历史 turn。这个平均口径含等待，与码表的最近窗口速率不同。累计 token 和费用包含原生用量中的工具参数、推理与压缩。

## 安装为本地插件

Linux 配套安装器自动安装插件、配置当前用户的 ChatGPT 应用菜单入口，并启动 HUD：

```bash
node scripts/install.mjs
```

安装器只增加用户级启动入口，不改系统安装文件。从应用菜单或原先绑定 `chatgpt.desktop` 的图标打开 ChatGPT 时，自动启用 `127.0.0.1:9222`，同时启动/复用检测器，用户无需输入调试参数。已经运行的 App 需要正常退出再打开一次；安装器不会终止聊天。依赖已打包，仅需 Node.js 22.15+ 与支持本地插件的 Codex CLI。安装解压包时会保留一份持久源码，临时解压目录可删除。

仅通过官方插件入口安装包时，需要执行该插件的 onboarding/setup，不能把插件清单当成会自动执行任意安装脚本的机制。setup 会配置同一持久启动入口。源码开发者仍可在仓库根目录用 `codex plugin marketplace add .` 与 `codex plugin add codex-speed-hud@agent-cost-monitor-local` 注册，再执行 setup。macOS / Windows 尚未实现持久启动入口。

恢复原启动入口：`node scripts/desktop.mjs remove`。存在原用户入口时会恢复备份；App 升级保留相同桌面 ID 时个人覆盖继续有效。直接执行 App 二进制、其他启动器或替换 Node 安装路径可能绕过这一入口，需重新运行 setup。

开启新聊天后可以说“启动 Codex Speed HUD”“查看 Codex Speed HUD 状态”“停止 Codex Speed HUD”。技能负责控制本机进程，后续更新不需要模型持续调用工具。没有默认生命周期 hooks。

卸载：先停止采集并用 `node scripts/desktop.mjs remove` 恢复启动入口，再运行 `codex plugin remove codex-speed-hud@agent-cost-monitor-local`。本地状态在 `~/.cache/codex-speed-hud/`（或 `$XDG_CACHE_HOME/codex-speed-hud/`），也可用 `CODEX_SPEED_HUD_DATA` 指定目录。状态文件只保留连接状态、聊天标识与数字，不保存正文或账号凭据。

## 验证与边界

```bash
npm test
npm run build
node scripts/preview.mjs
```

`demo/` 全部为合成数据，用来验证通知、聊天切换、工具等待和中断。预览页面本身不注入面板；通过 runner 的测试目标模式做真实 CDP 验证，或在预览中加载 `/hud.js`。

- 当前适配器根据本机 `/usr/lib/chatgpt/resources/app.asar` 中 preload 的消息转发实现编写，只读检查该文件。官方协议是数据格式参考，桌面事件旁听及悬浮层是非官方适配。
- 普通通知和 `codex-host-chunked-message-v1` 均支持。旁听器不发送 ACK，不改变原事件流；分块缺失时明确统计丢失数量。
- 只监听已打开的 App 页面，不额外启动 App Server、不调用 `thread/resume`。
- 模型生成工具名/参数属于输出用量，但当前安装版 App Server 没有工具参数的逐块生成通知；`item/commandExecution/outputDelta` 是程序 stdout/stderr。只读日志解析器需实际存在参数增量记录才能测量，默认日志缺失时保留原有快照。
- 只按当前聊天显示；主机未知或多个主机出现相同聊天 ID 时不混合。远程聊天可以显示观察到的正文流，但本机日志无法补齐远程原生 TTFT。
- 本机日志发现只覆盖最近最多 1200 个活动 session 文件；选中的日志从头分块扫描，每次最多 16 MB，后续增量读取。扫描完成前不把部分历史当作累计总量；不解析超过 2 MB 的单行。
- 对 App 更新、后台渲染进程、未持久化会话、页面中途附加等情况需要实际兼容验证。未启用调试接口时，不能声称已在真实桌面聊天上验证。
- 独立仓库仅包含速率插件，不包含 AgentCostMonitor 旧客户端或服务。
